# BiStudent — учёт посещаемости и успеваемости

Система для колледжа: электронный журнал преподавателя с отметкой посещаемости по распознаванию лиц.

- **Отметка посещаемости.** Камера в аудитории распознаёт студентов группы и ставит «П». Остальным в конце занятия ставится «Н».
- **Уважительные причины.** Отсутствие можно оформить как уважительное: болезнь, семейные обстоятельства, учебная или служебная необходимость, другое. К причине прилагаются отметка о документе и комментарий.
- **Электронный журнал.** Посещаемость, баллы за занятия по 100-балльной шкале, контрольные мероприятия (тесты, контрольные работы, экзамены, зачёты) и итоговый балл. Выгрузка в Excel в печатном виде.
- **Регистрация лиц по коду.** Преподаватель выдаёт группе код. Студенты сами делают три снимка на сайте с телефона или компьютера, преподаватель подтверждает снимки.
- **Учётные записи.** Администратор заводит преподавателей. Пароли хранятся в базе в виде хешей, вход можно запомнить на компьютере.

## Архитектура

| Часть | Технологии | Что делает |
|---|---|---|
| `BiStudent` | WinForms, .NET 10 | Клиент преподавателя: «Сегодня», «Отметка», «Расписание», «Журнал», «Группы», «Отчёт», «Администрирование». Камера подключается локально, кадры уходят на сервер. |
| `BiStudent.Server` | ASP.NET Core, EF Core (миграции), SQLite | REST API с bearer- и refresh-токенами, журнал и оценки, Excel/CSV (ClosedXML), статистика, распознавание (YuNet + SFace), сайт регистрации лица (`/register/`). |
| `BiStudent.Core` | OpenCvSharp | `FaceEngine`, ONNX-модели, общие контракты API (`BiStudent.Contracts`). |
| `BiStudent.Tests` | xUnit v3 | Тесты сервисов и API. |

```
[Камера] → BiStudent (WinForms) ──JSON──→ BiStudent.Server ──→ SQLite (C:\ProgramData\BiStudent)
[Телефон студента] → /register/ ─────────┘     └─ YuNet + SFace (распознавание)
```

## Запуск

Нужны Windows x64 и .NET 10 SDK.

```powershell
.\scripts\run-demo.ps1           # рабочий режим: пустая база, вход admin / admin со сменой пароля
.\scripts\run-demo.ps1 -Demo     # демонстрационные данные на пустой базе: teacher / teacher123
.\scripts\run-demo.ps1 -Reset    # удалить базу перед запуском (все данные будут потеряны)
```

Сервер слушает порт 5080 во всей локальной сети, чтобы студенты могли открыть сайт регистрации с телефона. При первом запуске Windows может спросить разрешение для брандмауэра.

Модель SFace (38 МБ) не хранится в репозитории: при первой сборке её скачивает `BiStudent.Core.csproj` из OpenCV Zoo (запасной адрес — Hugging Face) и проверяет по SHA-256. Без интернета положите `face_recognition_sface_2021dec.onnx` в `BiStudent.Core/Models` вручную.

### Где хранятся данные

- База и ключи шифрования лежат в `C:\ProgramData\BiStudent`, отдельно от папки программы. Поэтому обновление или повторная распаковка сборки не сбрасывает данные и пароли.
- Другой каталог задаётся через `Storage:DataDirectory`, отдельная строка подключения — через `ConnectionStrings:Default` (так делает Docker).
- База из прежнего места (`BiStudent.Server/App_Data`) при первом запуске переносится автоматически.
- Структура базы обновляется миграциями EF Core. Базы прошлых версий обновляются без потери данных: отметки «Опоздал» становятся «П», первая учётная запись получает права администратора.

### Учётные записи

- На пустой базе создаётся администратор (`Setup:AdminLogin` / `Setup:AdminPassword`, по умолчанию `admin` / `admin`). При первом входе система требует сменить пароль.
- Администратор заводит преподавателей в разделе «Администрирование», выдаёт временные пароли и отключает учётные записи.
- Сменить пароль: клик по имени внизу бокового меню → «Сменить пароль…».
- Флажок «Запомнить меня на этом компьютере» сохраняет refresh-токен, зашифрованный Windows DPAPI для текущего пользователя. Смена пароля завершает сохранённые сессии.

## Регистрация лица студентами

1. «Группы» → выберите группу → **Код регистрации**. Срок действия кода: от 1 часа до 7 дней. Код один на всю группу.
2. Студент сканирует QR-код или открывает ссылку (`http://<IP сервера>:5080/register/`) и вводит код.
3. Студент находит себя в списке группы, даёт согласие на обработку биометрических данных и делает три снимка: прямо, чуть влево, чуть вправо. Сервер сразу проверяет качество снимков.
4. Преподаватель открывает **Заявки на регистрацию**, смотрит снимки и подтверждает или отклоняет заявку. В распознавании используются только подтверждённые снимки.

Браузер телефона даёт доступ к камере только по HTTPS. В локальной сети без HTTPS сайт предлагает сделать снимки приложением камеры телефона. Для HTTPS-адреса укажите `Enrollment:PublicUrl`.

## Журнал

- В ячейке занятия стоит «П» или «Н». Уважительная причина отмечается жёлтым «Н» с пометкой и подсказкой: причина, документ, комментарий.
- Балл за занятие (1–100) ставится в той же ячейке. Контрольные мероприятия добавляет преподаватель кнопкой «Добавить контрольную».
- Справа: пропущенные часы (в том числе по уважительной причине), процент посещаемости, средний балл, итог. «Заполнить итог» выставляет среднее за семестр тем, у кого итога ещё нет. Итог можно исправить вручную.
- «Скачать Excel» формирует лист для печати: шапка, обозначения, примечания к уважительным причинам, строка подписи преподавателя.

## Docker и CI

```bash
docker compose up -d --build     # сервер на http://localhost:5080, база в томе bistudent-data
```

GitHub Actions (`.github/workflows/ci.yml`) на каждый push и PR собирает решение с `-warnaserror`, запускает тесты, выполняет самотест клиента и собирает Docker-образ сервера с проверкой `/health`.

## Режимы клиента для проверки

- `BiStudent.exe --self-test` — проверяет без сервера модели распознавания, список камер и отрисовку окна входа. Результат пишется в `diagnostics/result.txt`.
- `BiStudent.exe --screenshots http://localhost:5080 <логин> <пароль>` — входит на сервер и сохраняет скриншоты всех разделов в `diagnostics/`.

## Резервные копии

- Сервер сам делает копию раз в сутки и хранит последние 7 в `<каталог данных>/backups`.
- Ручная копия, скачивание и восстановление — «Администрирование» → «Резервные копии».
- Копия — zip со снимком базы, манифестом и ключами шифрования образцов лиц. **Храните файл как пароль:** по нему можно расшифровать биометрию.
- Копии прошлых версий при восстановлении обновляются миграциями.

## Данные и приватность

- Биометрия хранится только на сервере. Образцы лица 112×112 зашифрованы ASP.NET Data Protection, полные кадры с камеры и сайта не сохраняются.
- Снимки заявки удаляются после её рассмотрения. При подтверждении они становятся образцами лица студента.
- Удаление студента удаляет его образцы, заявки, отметки и оценки.
- Камеру и регистрацию лиц используйте только с согласия студентов и учебного заведения.

## Ограничения распознавания

- Сильный поворот головы, плохой свет и перекрытое лицо мешают распознаванию. Отсутствие отметки означает только, что студента не удалось надёжно распознать.
- **Программа не проверяет, что перед камерой живой человек:** фотография на телефоне может дать ложную отметку. Преподаватель проверяет отметки и может исправить их вручную.
