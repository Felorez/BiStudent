# BiStudent — посещаемость без переклички

Система учёта посещаемости для колледжа. Преподаватель работает в приложении для Windows (WinForms):
- камера в аудитории узнаёт студентов и сама ставит отметки;
- расписание вводится один раз на семестр;
- журнал выгружается в Excel одной кнопкой;
- студенты с частыми пропусками попадают в «зону риска» автоматически.

Данные, распознавание лиц и отчёты обслуживает сервер API.

## Архитектура

| Часть | Технологии | Что делает |
|---|---|---|
| `BiStudent` | WinForms, .NET 10 | Клиент преподавателя: «Сегодня», «Автоотметка», «Расписание», «Журнал», «Группы», «Отчёт для руководства». Камера подключается локально, кадры уходят на сервер. |
| `BiStudent.Server` | ASP.NET Core, EF Core, SQLite | REST API с bearer-токенами: расписание, отметки, журнал, Excel/CSV (ClosedXML), статистика, распознавание (YuNet + SFace), демо-данные. |
| `BiStudent.Core` | OpenCvSharp | `FaceEngine` и ONNX-модели, общие контракты API (`BiStudent.Contracts`). |
| `BiStudent.Tests` | xUnit v3 | Тесты сервисов и API. |

```
[Камера] → BiStudent (WinForms) ──HTTPS/JSON──→ BiStudent.Server ──→ SQLite (/data)
                                                     └─ YuNet + SFace (распознавание)
```

## Быстрый старт демо

Нужны Windows x64 и .NET 10 SDK.

```powershell
.\scripts\run-demo.ps1          # собрать, запустить сервер и открыть клиент
.\scripts\run-demo.ps1 -Reset   # то же со свежими демо-данными
```

Вход в клиент: сервер `http://localhost:5080`, логин `teacher`, пароль `teacher123`.

Модель распознавания SFace (38 МБ) не хранится в репозитории: при первой сборке её скачивает `BiStudent.Core.csproj` из OpenCV Zoo (запасной адрес — Hugging Face) и проверяет по SHA-256. Без интернета положите файл `face_recognition_sface_2021dec.onnx` в `BiStudent.Core/Models` вручную. Детектор YuNet (0,2 МБ) лежит в репозитории.

Запуск вручную:

```powershell
dotnet run --project BiStudent.Server --urls http://localhost:5080
dotnet run --project BiStudent
```

При первом запуске сервер создаёт базу `BiStudent.Server/App_Data/bistudent.db` и заполняет её демо-данными:
- преподаватель, две группы и расписание по звонкам колледжа;
- четыре недели посещаемости.

Список студентов сервер берёт из `BiStudent.Server/seed/students.local.csv` (формат `ФИО;Группа`). Этот файл не попадает в git и в образ Docker. Если его нет, используется вымышленный `students.demo.csv`.

## Как показать руководству (5 минут)

1. **Сегодня.** Посещаемость за неделю, число автоотметок, сэкономленное время и зона риска на одном экране.
2. **Автоотметка.** Запустите камеру на текущей паре. Студенты получают отметку сами, опоздания фиксируются автоматически, счётчик показывает время, сэкономленное на перекличке.
3. **Расписание.** Шаблон недели на семестр: чётные и нечётные недели, разовые занятия, отмена пары в один клик, импорт из CSV.
4. **Журнал.** Матрица «студенты × занятия» с правкой по клику, затем «Скачать Excel».
5. **Отчёт для руководства.** «Было → стало», графики и расчёт на весь колледж (поле «Если перейдут N преподавателей…»). Отчёт можно сохранить в PNG или распечатать.

Параметры расчёта задаются в `BiStudent.Server/appsettings.json` (раздел `Automation`):
- `SecondsPerManualMark` — секунд на одну фамилию при перекличке;
- `MinutesPerManualReport` — минут на ручное сведение журнала.

## Docker и CI

```bash
docker compose up -d --build     # сервер на http://localhost:5080, база в томе bistudent-data
```

GitHub Actions (`.github/workflows/ci.yml`) на каждый push и PR:
- собирает решение с `-warnaserror` и запускает тесты;
- выполняет самотест клиента;
- собирает Docker-образ сервера и проверяет `/health`;
- для `main` выкладывает готовые сборки клиента и сервера для Windows (self-contained) как артефакты.

## Режимы клиента для проверки

- `BiStudent.exe --self-test` — проверяет без сервера модели распознавания, список камер и отрисовку окна входа. Результат пишется в `diagnostics/result.txt`.
- `BiStudent.exe --screenshots http://localhost:5080 teacher teacher123` — входит на сервер и сохраняет скриншоты всех разделов в `diagnostics/`.

## Данные и приватность

- Биометрия хранится только на сервере: образцы лица 112×112 зашифрованы ASP.NET Data Protection, полные кадры с камеры не сохраняются.
- Удаление студента удаляет его образцы и отметки.
- Камеру и регистрацию лиц используйте только с согласия студентов и учебного заведения.

## Ограничения распознавания

- Распознавание использует YuNet для поиска лица и SFace для сравнения эмбеддингов после выравнивания по пяти точкам.
- Порог `FaceEngine.MatchThreshold` и разницу между двумя лучшими кандидатами нужно проверить на реальных условиях класса.
- Сильный поворот головы, плохой свет и перекрытое лицо мешают распознаванию.
- Отсутствие отметки означает только, что студент не был надёжно распознан.
- **Программа не проверяет, что перед камерой живой человек:** фотография на телефоне может дать ложную отметку. Преподаватель должен проверять записи и иметь другой способ отметить присутствие.
