# BiStudent — посещаемость по камере

Настольное приложение для преподавателя на Windows. Вход — через Firebase Authentication, слева две страницы: **Студенты** и **Камера**. Оценки открываются из списка студентов.

## Запуск

Нужны Windows x64, .NET 10 Desktop Runtime и веб-камера. Откройте `BiStudent.slnx` в Visual Studio или выполните:

```powershell
dotnet restore BiStudent\BiStudent.csproj
dotnet run --project BiStudent\BiStudent.csproj
```

Модели обнаружения YuNet и распознавания SFace уже лежат в `BiStudent/Models`. Пакеты устанавливаются из NuGet. При первом запуске база создаётся в `%LOCALAPPDATA%\StudentAttendance\attendance.db`.

## Авторизация

В Firebase Authentication проекта `bistudent` создана учётная запись **Ниязова Мадина Ержанкызы**, email `madina.niyazova.2023@mail.ru`. Вход Email/Password включён. Приложение проверяет пароль через Firebase REST API и допускает только UID преподавателя из `firebase.json`. Самостоятельной регистрации нет.

Файл `firebase.json` должен находиться рядом с исполняемым файлом; сборка копирует его автоматически. Пароль не входит в исходники и сборку. Для входа, загрузки группы и сохранения оценок нужен интернет. По умолчанию включено **Запомнить устройство**: зашифрованный refresh token сохраняется для текущего пользователя Windows. После закрытия приложения вход восстанавливается через Firebase. Кнопка **Выйти** удаляет сохранённый вход и возвращает окно пароля.

Firebase Authentication хранит учётную запись преподавателя. Cloud Firestore хранит выбранную группу, список студентов, шесть предметов и оценки. После входа группа загружается на любом компьютере. Правила доступа находятся в `firestore.rules`: доступ разрешён только UID преподавателя и только выбранной группе. Образцы лиц и посещаемость синхронизируются с закрытыми коллекциями Firestore и кэшируются локально в SQLite. Локальные образцы зашифрованы Windows DPAPI. Расписание добавляется локально; при восстановлении посещаемости восстанавливаются и связанные занятия. Реальный список студентов не включается в исходники или сборку.

## Студенты и расписание из версии друга

В исходниках сохранён `starter-data.json` с демонстрационными данными версии `55c194c` для локального режима (`useCloudData: false`). В режиме Firebase автоматический импорт этих данных отключён: интерфейс показывает только выбранную облачную группу. Старые локальные данные сохраняются, но другие группы скрыты.

Выберите студента и нажмите **Обновить лицо**, чтобы зарегистрировать его для распознавания на всех устройствах через облачную синхронизацию. Занятия своей группы добавьте на странице камеры; расписание демонстрационных групп к ней не применяется.

## Оценки

Выберите студента на странице **Студенты** и нажмите **Оценки**. В облачном режиме доступны ровно шесть заданных предметов. Для каждого студента по каждому предмету хранится журнал максимум из **100 оценок**, каждая с баллом **0–100**, датой `ГГГГ-ММ-ДД` и комментарием. **Добавить новую оценку** создаёт отдельную запись, в том числе в тот же день. Чтобы исправить или удалить запись, выберите её в журнале и используйте отдельную кнопку. Средний по предмету и общий средний в списке студентов рассчитываются по всем сохранённым оценкам, а не по последним оценкам или средним предметов. Лимит проверяется перед добавлением; атомарная запись с проверкой версии предотвращает превышение лимита при добавлении с разных устройств. Пустая оценка отображается как «—» и не учитывается в среднем балле. После входа прелоадер загружает всю группу и журнал в общий кэш. Открытие окон, добавление, исправление и удаление оценок работают локально. По умолчанию каждые **5 секунд** проверяются локальные изменения: при их отсутствии запросов к Firebase нет; изменённые записи отправляются пакетом на предмет без повторного чтения базы. Кнопка **Сохранить изменения** доступна только при наличии изменений. Через **⚙** рядом с именем преподавателя можно задать интервал от 1 до 3600 секунд; настройка сохраняется на компьютере. Локальный черновик восстанавливается после перезапуска, а при выходе выполняется попытка сохранения. Кнопка **Обновить из Firebase** вручную загружает данные другого устройства, если нет несохранённых изменений. Одновременное редактирование защищено проверкой версии документа. Вместе с оценкой сохраняются имя и Firebase UID преподавателя.

## Использование

1. После входа дождитесь загрузки группы. Выберите студента и нажмите **Обновить лицо**: сделайте три снимка через камеру — прямо, немного влево и немного вправо. Прежние образцы LBPH не используются, а история посещаемости сохраняется.
2. На странице **Камера** добавьте занятия в расписание. Группа и один из шести предметов выбираются из списков.
3. Во время занятия нажмите **Запустить**. Текущее занятие определяется по дню недели и времени компьютера. Если в расписании два занятия одновременно, автоматическая отметка останавливается до исправления расписания.
4. Зелёная рамка означает совпадение с зарегистрированным студентом, красная — неизвестное лицо. После пяти последовательных совпадений запись добавляется один раз для этого занятия и даты.
5. Отметку можно поставить или снять вручную в таблице посещаемости.

В базе хранятся только обрезанные образцы лиц, зашифрованные через Windows DPAPI для текущей учётной записи. Полные кадры с камеры не сохраняются. Удаление студента удаляет его образцы, отметки и оценки.

## Сайт статистики

В `student-site` находится готовый статический сайт для Netlify и любого HTTPS-хостинга. Регистрация посетителей не нужна. Сайт делает один GET к публичному документу `publicStats/23-po-103-4r-2` и хранит ответ в localStorage 60 секунд. Поиск и переключение разделов не обращаются к Firebase. При отсутствии оценок показывается центральная анимированная волна, в пустом журнале — «Данных нет».

Обновлённое приложение преподавателя публикует отдельный снимок оценок и сохранённых отметок присутствия после изменений. Перед записью сравнивается локальный хэш: неизменившийся снимок повторно не записывается. Посетителям доступны имя студента, предмет, оценка, дата и отметки присутствия; комментарии к оценкам, пароли, токены и образцы лиц в публичный снимок не входят. Основные коллекции остаются доступны только преподавателю. Публичное правило чтения настроено отдельно в `firestore.rules`.

### Ограничения распознавания

Камера запрашивает HD 1280×720 через DirectShow/MJPEG; фактический режим зависит от устройства. Распознавание допускает лица от 36 пикселей по обеим сторонам вместо прежних 65, а для более мелких обнаруженных лиц показывает «Подойдите ближе». Порог совпадения SFace 0,43, разница между кандидатами 0,06 и подтверждение по пяти кадрам сохранены. Контроль `--distance-check` локально проверяет уменьшенные образцы в HD-кадре без изменения базы и отправки изображений. Такая проверка не заменяет проверку расстояния, света и резкости в аудитории.

Распознавание использует YuNet для поиска лица и SFace для сравнения эмбеддингов после выравнивания по пяти точкам. Порог `FaceEngine.MatchThreshold` и разницу между двумя лучшими кандидатами нужно проверять на реальных условиях класса. Сильный поворот головы, плохой свет и перекрытое лицо всё равно могут помешать. Отсутствие отметки означает только, что студент не был надёжно распознан. **Программа не проверяет, что перед камерой живой человек:** фотография на телефоне может дать ложную отметку. Перед использованием как официального журнала преподаватель должен проверять записи и иметь другой способ отметить присутствие. Камеру и биометрические образцы используйте с разрешения участников и учебного заведения.

KimTools не подключён: библиотека требует лицензию разработчика, которой пока нет. Интерфейс выполнен собственными WinForms-контролами с двойной буферизацией и единой тёмной темой.



## Регистрация лица с сайта

1. В приложении: **Студенты** → выберите студента → **Код регистрации лица на сайте**. Код действует 24 часа и принимает одну отправку. Выдача нового кода отключает предыдущие коды этого студента.
2. Студент на сайте открывает **Зарегистрировать лицо**, вводит код, выбирает камеру и делает три снимка: прямо, немного влево и вправо. Учётная запись студента не нужна.
3. Преподаватель входит в приложение или нажимает **Обновить из Firebase**. Приложение проверяет единственное лицо на каждом снимке, выравнивает его и сохраняет три подготовленных образца в `groups/<group>/faces/<studentId>`.
4. На других устройствах образцы загружаются через прелоадер после входа. Ошибочные снимки не заменяют прежнее лицо; преподаватель выдаёт новый код.

Лица и отправки не включаются в публичный документ статистики. Firestore Rules закрывают их чтение для посторонних; студент может создать единственную отправку по своему секретному коду. После успешного переноса отправка удаляется, а код отключается.

**Выбрать камеру** на странице камеры и **Выбор камеры** в обновлении лица показывают устройства Windows. Выбранное устройство запоминается по DevicePath, поэтому смена порядка USB-устройств не меняет выбор.
